# ZV67 — проверка осуществимости (G0)

**Дата проверки:** 23 октября 2026.  
**Область:** реальный backend Google AI Mode, OpenCodeX, Responses API, Codex Desktop.

Документ разделяет подтверждённые факты, технические ограничения и непроверенные возможности. Ни одна неподтверждённая возможность не считается реализованной.

## 1. Лицензия и условия XD06/google-ai-mode

Проверено через GitHub API 23 октября 2026:

```text
repos/XD06/google-ai-mode
license: null
private: false
```

У репозитория нет лицензии. Публичный README прямо указывает, что проект нарушает условия использования Google и предназначен только для личного исследования. Копирование или переработка его исходного кода в ZV67 не выполняется.

README также описывает двухуровневый движок:

1. Запросы через `curl_cffi` с имитацией TLS-отпечатка Chrome.
2. При блокировке `SG_REL` — переход на реальный Chrome через CDP, чтобы обойти обнаружение автоматизации.

Второй механизм является обходом антибот-защиты. Техническое задание ZV67 запрещает реализацию такого обхода. Поэтому подход XD06 не может быть воспроизведён в ZV67.

## 2. Google AI Mode

Подтверждённые ограничения:

- Официального API для Google Search AI Mode нет.
- Доступ основан на неофициальном протоколе поиска и требует cookies авторизованной сессии.
- Протокол может измениться без предупреждения.
- Использование может нарушать условия обслуживания Google.
- Google не предоставляет достоверных данных об остатке квоты для сторонних клиентов.

Непроверенное:

- актуальная последовательность запросов и формат ответа AI Mode;
- стабильность сохранения контекста;
- поддержка streaming;
- пригодность AI Mode для структурированных вызовов инструментов.

Реальные Google-аккаунты не использовались. Авторизация Google не выполнялась.

### Вывод по backend

Собственный адаптер, соответствующий ограничениям задания, может использовать только разрешённые Google интерфейсы. Сейчас такой интерфейс не подтверждён. Механизм обхода TLS-фингерпринтинга и антибот-защиты не реализуется.

**Статус Google AI Mode Backend: UNSUPPORTED до появления разрешённого официального способа доступа.**

Это ограничение не блокирует остальные компоненты: API, управление аккаунтами, маршрутизацию, сессии, статистику, панель и установку можно реализовать и проверить с mock-провайдером.

## 3. OpenCodeX

Подтверждено:

- установлен глобальный пакет `@bitkyc08/opencodex@2.91.0`;
- рабочий порт — `10100`;
- конфигурация находится в `~/.opencodex/config.json`;
- провайдеры описаны объектом `providers` с полями `adapter`, `baseUrl`, `apiKey`, `models` и другими;
- Codex CLI использует `openai_base_url = http://127.0.0.1:10100/backend-api/codex`;
- каталог моделей Codex берётся из `~/.codex/opencodex-catalog.json`.

Непроверенное:

- точный формат добавления нового локального provider без поломки существующих;
- отображение модели в нативном селекторе Codex Desktop;
- поддержка Responses API и инструментальных вызовов для нового provider.

Изменение конфигурации OpenCodeX выполняется отдельным этапом после резервного копирования.

## 4. Codex и Responses API

Установленная конфигурация Codex использует OpenCodeX как OpenAI-совместимый backend. Фактический набор полей Responses API, который отправляет текущая версия Codex, ещё не зафиксирован.

До реализации `/v1/responses` необходимо записать реальные запросы клиента и проверить:

- структуру `input`;
- события streaming;
- формат `function_call` и `function_call_output`;
- идентификаторы и отмену.

Статус: **NOT TESTED**.
